从**配置进度 › 应用配置**进入应用设置与**配置参数**，保存照明、暖通空调、室内环境与能源的设置，再到[部署与交付](/platform/deployment)实施现场配置。**期望配置**指对应设备需要应用的目标配置及版本，用于与现场实际结果比较。

<Note>
  规划已保存、配置已批准、设备已应用与测试已验证分别判断。实际生成、下发与应用须以可用执行服务、当前期望配置版本和真实设备回执为准；演示结果不能作为验收证据。
</Note>

## 应用设置

先核对项目采用的规范、空间用途、型号与固件能力、参数模板及作用范围，再确定具体值。

配置参数按 **项目 → 楼宇 → 楼层 → 功能区**继承。为下级覆盖时写明范围、值与原因；删除覆盖后恢复上级继承。项目不会自动采用新模板，模板更新由机构管理员核对并采用，再检查保留值及待批准项。

<AccordionGroup>
  <Accordion title="照明" description="先确认回路与传感关系，再设定控制行为。">

    - 核对开灯策略、**占用三段**、有人亮度、恒照度目标、手动后恢复自动，以及时间安排和失联回退。占用三段说明无人后的延时、待机亮度与时长、结束动作。
    - 逐回路核对开关型或调光型、驱动下限及真实负载。开关型设备不能执行中间百分比调光。
    - 需要恒照度控制的回路组，确认唯一且有效的控制照度源；分别核对占用、额外跟随占用与诊断照度来源。
    - **照明控制参数**区分楼层默认与功能区覆盖；可调范围取机构管理员批准的配置参数。保存后仍要核对对应控制器的同步结果。

    测试时对照实际动作、调光下限、走动响应与照度读数，不只看界面值已改变。

  </Accordion>
  <Accordion title="暖通空调" description="按风机盘管、多联机与只计量的分体空调分别核对。">

    - **风机盘管**：核对水系统、设定范围、待机与节能、面板锁、防冻、断电恢复和通信中断策略。季节计划不能代替现场冷热源条件。
    - **多联机**：核对内外机对应关系、可写范围、无人策略、写入限制与原厂保护。待机、节能策略不直接套用于多联机。
    - 多联机逐外机核对原厂限温、线控器禁止项、模式、来电自启和设定步长。需要在原厂控制器完成的设置，现场设置后登记确认，平台不代替原厂设置。
    - **分体空调**仅计量用电，不作为平台控制对象。中央系统的可写点须先通过控制验证。

    **暖通空调设置**选择适用楼层并查看当前值；保护、限温与回退等配置在**配置参数**中逐项核对。

  </Accordion>
  <Accordion title="室内环境" description="确认测量能力、采集代表性与统计条件。">

    - 按真实器件与接入能力确认温湿度、CO₂、PM2.5 等指标、单位、数据来源与更新时间。
    - 为各空气质量传感器登记采集位置，以及读数代表整个功能区、局部还是尚待核对。
    - 参考范围、统计窗口、告警进入与解除、缺测处理在**配置参数**中核对；**室内环境设置**不另填一套阈值。
    - 需要校准或能力验证时，保存对象、方法和结果。缺失数据保留缺测状态，不能按零值或正常值处理。

    瞬时读数、统计均值与告警结论的时间条件不同，测试和运营交接时分别说明。

  </Accordion>
  <Accordion title="能源与碳排放" description="先明确计量边界，再核对费用、基线与排放口径。">

    - **能耗设置**选择已登记的计量来源，核对总表、分表、所属总表、覆盖楼层与计入方式，避免总分表重复计入总量。可以先保存设置，数据验证通过后才用于用电统计。
    - 倍率、起始底数等来自**系统接入 › 数据映射**；能耗设置登记计量边界、折标系数、基线与计费方式，不重复登记原始点表。
    - 费用按正式供电资料及生效时间登记；费用结果是估算。节能基线须满足有效历史计量数据及相应模型条件。
    - **碳排放设置**登记 CO₂ 或 CO₂e 口径、因子与单位、年份、地区、来源、用途、有效区间及核算边界。没有适用因子的日期不套参考因子。
    - 启用需量限制前，须登记现场测试记录并由机构管理员批准相应参数；地方能耗平台的**对外上传**设置仅由机构管理员登记，上传结果以接收平台回执为准。

    能耗、碳排放设置保存形成各自版本。排放因子、折标系数和电价在配置参数中只读引用对应设置，不重复修改或批准。

  </Accordion>
</AccordionGroup>

**跨应用条件一起核对**：项目时区、工作时间与节假日表、室外温湿度来源、时间同步、执行位置、动作优先级、通信中断及保护边界。工作时间与节假日表在**场景 › 定时**中登记，室外来源在**系统接入**中核对；控制策略不能替代设备本地或原厂保护。

## 配置参数与批准

配置人员提交的**适用规范登记**需机构管理员批准；机构管理员保存登记直接生效。应用设置保存形成版本，配置参数值与下级覆盖则按参数批准规则处理。

<Steps>
  <Step title="核对并保存修改">

    核对配置项、完整范围、目标值、单位、依据与执行位置。修改参数或下级覆盖时填写变更原因；已批准值改变后，回到**待批准**。

  </Step>
  <Step title="补齐能力与测试依据">

    对**待验证**项核对型号、固件及测试要求，登记测试编号、方法、对象、结果和值与版本。未通过或结果待确认不能标为已验证；参数测试记录也不代替设备应用回执。

  </Step>
  <Step title="由机构管理员批准">

    管理员逐项或通过**批准所选**核对具体值、完整范围、参数版本、依据与能力条件。提交时内容或版本变化，应重新审阅后批准。

  </Step>
  <Step title="核对期望配置与现场应用">

    查看**下发包预览**及未进入的项目和原因，再核对设备期望配置版本与逐台应用回执。预览和批准都不等于已发送到现场。

  </Step>
</Steps>

| 状态或资料 | 如何判断 |
| --- | --- |
| **待批准 / 已批准** | 是否已允许相应参数执行；不能据此判断现场生效。 |
| **待验证 / 已验证** | 能力或测试依据是否有效；已验证须关联对应对象、值与版本的测试记录。 |
| **待核对** | 仍有资料或条件需确认，按该项说明处理。 |
| **配置同步** | 对应设备是否有真实的应用成功回执，且匹配当前期望配置版本。 |
| **平台规定 / 引用设置** | 平台规定只读；引用设置返回对应应用设置修改，不在参数表重复批准。 |

若提示**待生成到网络配置**，说明批准参数尚未生成到设备的期望配置。当前批准参数进入下发包后的生成与执行服务尚未接通，不能把批准当作设备已应用；须生成、下发并核对真实回执后继续验证，已有交付也不覆盖新增批准项。

配置资料与批准条件准备后，继续[部署与交付](/platform/deployment)，核对现场应用、测试与交付。
