面向安装、调试人员与集成商。按已核验的设计安装设备，把现场实物、平台点位与测试记录对应起来，再按完整设备网络完成交付。

**实施顺序：核对资料 → 安装与接线 → App 现场部署 → 调试验证 → 交付交接。** 设计尚未确认时，先完成[智能建筑设计指南](/guides/design)中的范围、选型与接口核对。

<Note>
当前部署 App 的登录、下载、现场连接、记录上传及差量同步仍为演示流程；以下现场部署与验收步骤须在真实身份、部署和执行服务可用的版本中完成，演示结果不能作为验收依据。
</Note>

## 核对设备与资料

施工前将图纸、设备清单、应用要求和人员分工对应到同一项目与实施版本，确认哪些内容已经核实、哪些仍待处理。

| 资料 | 安装前核对 |
| --- | --- |
| **图纸与点位** | 楼宇、楼层、图纸版本、比例尺、功能区、点位名称与安装位置；改造项目同时核查现有接线。 |
| **设备与接线资料** | 实际型号、硬件与固件、数量、附件、对应批次的安装说明与接线图，以及驱动、负载和原厂系统兼容记录。 |
| **网络与系统接入** | 每个设备网络的网关、全部服务楼层、成员、中继和代理；网关上联条件及第三方设备点表。 |
| **应用与测试要求** | 本次启用的功能、工作时间、项目时区、需批准的配置、测试对象、预期动作与断联恢复要求。 |
| **交接安排** | 安装、配置、批准、测试及交付负责人，遗留事项处理方式和运营、维护联系人。 |

在 PACOM Station 的**准备现场绑定**中核对已保存的网络版本、服务楼层、待绑定点位和可部署成员。导出同一保存版本的 **PDF 现场安装图**与 **Excel 设备清单**，用于定位、布线和安装；规划变化后重新生成，撤下旧资料。

现场安装资料不含设备身份和网络密钥，不能用于实际绑定，也不证明配置、测试或交付完成。项目自备的系统图、原厂接口资料和型号接线图仍须齐备。

**明确分工**：机构管理员或获本项目授权的配置人员可规划、部署和测试；配置批准、密钥更新与最终交付确认由机构管理员完成。部署人员使用本人账户，提前核对项目授权、机构订阅与剩余设备额度。未订阅或额度已满时不能绑定或接入新设备，联系机构管理员处理。

详细准备步骤见[准备现场实施](/platform/deployment#现场实施准备)。

## 确认现场条件

先走查实际安装范围，核对实物与图纸的差异，再组织安装；不能只根据图纸上的距离或覆盖圈判断现场可用。

- **安装位置**：核对固定方式、遮挡、气流、热源、散热和检修空间。设备安装位置与服务功能区分别确认，装在走廊的设备也可能服务邻室。
- **供电与负载**：按对应型号的有效资料核对电源、线路、负载、驱动与保护条件；平台规划检查不能替代实际接线、兼容和带载检查。
- **网关上联**：与项目 IT 人员确认实际联网方式、地址分配、上网条件和故障排查责任。所需域名、端口与安全配置按网关版本的接入资料实施。
- **设备网络**：核对网关最终位置、走廊与竖向连通路径、中继和代理。跨层网络逐层检查；相邻逻辑网络仍需考虑共同无线环境。
- **现场工具**：准备匹配的安装与测量工具、点位标签及可用手机。App 支持的手机系统与版本按实际发布资料确认，首次打开网络需联网取得资料。

分别检查**网关联网**与**设备网络**，前者正常不能代替后者正常。现场不符时记录具体点位、差异与处理人，先核对调整，再沿用新的资料施工。

有未保存规划先保存并检查，处理**规划检查**中的阻止项。比例尺、角色建议等提示与阻止项分开，不能把提示清零当作所有设备已经安装或验证。

## 设备安装与接线

具体固定、端子、线缆和上电要求以对应型号、硬件版本及本批次有效安装资料为准。产品外观图只能帮助辨认位置，不能据图推定电压、接口版本、防护等级或接线能力。

涉及电源、照明负载和空调系统的接线由相应专业人员实施；接线前按现场安全要求隔离电源，完成接线检查后再分阶段上电。资料与实物端子不一致时先核实，不凭相同插头外观混接，也不自行组合不同供电方式。

| 设备 | 安装与连接重点 |
| --- | --- |
| **边缘网关 EG20** | 与配套 WA20 一起核对，按实际位置安装，保留供电、上联及检修条件。检查机柜与金属遮挡，按最终组合验证无线通路。 |
| **无线适配器 WA20** | 按已确认的配套接口方案安装，与网关、适配器身份和兼容版本逐项核对；具体连接方式以对应安装资料为准，不能拿产品图片代替接口资料。 |
| **多功能传感器 MS20** | 按实际活动位置核对安装与遮挡，测试走动及座位小幅活动；供电归属按接线确认，与回路组、占用跟随和照度角色分别登记。 |
| **空气质量传感器 AQ20** | 先取得已确认型号的指标、安装及校准资料；核对测点代表范围、气流影响、单位和接入方式，不能借用其他产品的安装参数。 |
| **照明控制器 LC20** | 用于正常照明，消防应急照明不纳入其控制。核对单回路开关或 0–10 V 调光、外部驱动与实际负载；首版不按 DALI 或 1–10 V 接线。传感器供电按本批次资料选择，避免重复供电。 |
| **多联机空调网关 VG2x** | 按双方接线图与点表连接，核对品牌、机型、内外机对应及原厂限制；按系统接入处理，不作为 Mesh 节点绑定。 |
| **风机盘管温控器 FC20** | 核对两管制或四管制、水温传感器、电加热及实际阀、风机接口；按实物端子图接线，确认室温来源与原厂保护。 |
| **触控面板** | 核对固定、供电、可操作对象及匹配接入方案；当前平台接入待确认，不能因图上已有点位便按已支持接入施工。 |
| **自发电无线开关** | 按已确认的接收与适配方案安装，核对操作映射及现场覆盖；当前暂不支持平台绑定，不能按普通 Mesh 节点处理。 |

按以下顺序留下现场对应关系：

1. **定位与标识**：逐层核对点位、实物型号、安装位置和标签；点位名称便于定位，真实设备身份在绑定或接入时另行确认。
2. **固定与布线**：按型号资料安装设备和附件，保留检修条件，核对线缆标识、连接路径与实际服务对象。
3. **复核与上电**：检查供电、端子、负载及驱动后分阶段上电，核对本机行为；出现异常先处理，不以平台在线代替电气检查。
4. **回写现场事实**：保存位置、接线、供电归属和接口的差异，更新相应规划与安装资料；图上移动点位或改供电关联不会改变实际接线。

供电关系不等于数据通信：LC20 与 MS20 的供电连接、网络通信、回路组及控制照度源各自核对。未按实际接线确认的“系统建议”不能当作安装事实。第三方系统与计量来源还须核对地址、单位、倍率和读写范围，后续进入[系统接入](/platform/integrations#连接与验证)验证。

## 安排安装与调试

**PACOM Station 管理规划、期望配置、全网体检与交付；部署 App 是独立现场工具，完成身份确认、绑定、配置和局部测试。** 绑定、配置应用与功能验证分别保留结果，不用一个“完成”代替全部状态。

### 现场部署

<Steps>
  <Step title="先绑定网关，建立设备网络">

    按图纸核对实际网关，在 App 依次完成**连接网关 → 配置上联 → 建立网络**。网关位置不符时先在 Station 调整点位。只有网关已绑定的网络才能绑定成员设备；规划网络或标记网关不等于真实网络已建立。

  </Step>
  <Step title="打开网络，核对全部服务楼层">

    用本人账户打开有权部署的网络，取得网络资料，核对网络版本、图纸和点位。App 按整个设备网络读取全部服务楼层，可切换楼层；没有本网络点位或图纸的楼层仍会列出并注明情况。Station 中选择某一层不等于裁切网络成员。

  </Step>
  <Step title="由近及远，按回路绑定设备">

    从网关所在楼层与附近设备开始，再推进到相邻楼层。以回路为单位，将实际控制器与供电传感器对应到正确点位，核对真实硬件身份及绑定回执；不能仅靠名称、位置或附近信号判断绑定成功。App 采用平台已采纳的中继与代理规划。

  </Step>
  <Step title="核对配置与首次上报">

    逐台核对当前**期望配置第 N 版**、应用结果与首次数据上报。配置部分失败时查看失败项与原因，核对后补齐，不把已经绑定的设备一律复位重绑。结果未知时先查询原请求与实际状态，避免重复执行。

  </Step>
  <Step title="就地测试，并上传记录">

    按已确认的测试计划，分别对回路组或单独设备执行现场测试，记录实际动作与未通过项目。App 在线时上传绑定、配置、测试与现场改动；在 Station 的**功能验证**核对收到的记录、覆盖设备和测试版本。保存验证计划只是计划，不能代替现场测试。

  </Step>
</Steps>

| 结果 | 完成依据 |
| --- | --- |
| **已绑定** | 实际硬件身份与 App 绑定回执对应当前点位；没有手动设为已绑定的入口。 |
| **配置已应用** | 逐项应用结果匹配设备当前期望配置版本，旧版本回执不算当前同步。 |
| **在线** | 有有效通信与最近上报，读数和状态同时核对；网关离线时下游可能是“状态未知”。 |
| **已验证** | 测试回执点名覆盖设备，保留测试项目、结果、期望配置版本、执行人与时间。 |

网络版本写 **vN**，设备期望配置写**第 N 版**，两者分别核对。单台设备或同回路其他设备通过，不能推定未被回执覆盖的设备也通过。

### 现场改动与异常

<AccordionGroup>
  <Accordion title="现场接线或负载与规划不符" description="记录真实值，核对并入与受影响设备。">

    改供电、驱动或回路组时，记录改动前依据、现场值、网络版本、已执行对象、提交人、时间与手机。供电或回路组改动用**下发并上传**；驱动登记用**保存并上传**，不能把只改资料的动作写成硬件已执行。

    Station 按现场值核对并入，形成新的网络版本。能落入当前规划的值自动并入；平台之后改过同项时仍按现场值并入。点位已删除、移网或关系不再适用时保留**待并入**，先调整规划再完成并入；涉及设备暂不按规划覆盖下发，也不能按已同步交付。

    App 不自行编新版本，联网后差量同步变化的点位配置与图纸。并入后核对哪些回执仍有效、哪些设备需补配置或重新测试。

  </Accordion>
  <Accordion title="没有数据、配置失败或设备被复位" description="先判断状态，再选对应处理方式。">

    无数据时先核对网关上联、设备供电、通信与最近上报；网关离线时不能把下游“状态未知”当成全部设备故障。配置失败查看设备**配置**中的逐项结果，补齐后重新核对；尚未确认原请求结果时先查，不重复下发。

    **待绑定（被现场复位）**表示设备已经退网并清除配置，须补绑回原点位、重新配置和测试，旧验证不计入，不能直接用“重新下发”代替补绑。只有离线没有复位依据时，不推定已经复位。远程补绑只用于身份已知且符合条件的设备；未知身份仍需现场识别。

    具体处理见[维护设备与网络](/platform/devices#设备与网络维护)。

  </Accordion>
  <Accordion title="增补或更换设备" description="保留规划与历史，重新确认现场身份和结果。">

    增补时保存新增点位形成新网络版本，在 App 打开原网络、同步新资料，再补绑、核对配置与局部测试。已有网络不重复首次网关绑定；各层代理交付后仍保持常开，供 App 连接。

    更换硬件使用对应维护流程，把新设备绑定到原点位并重新验证，不能沿用旧硬件测试结论。设备恢复出厂、换设备或补绑所需的新地址由服务处理，安装人员不自行填写或复用旧地址。网关与适配器更换、移除设备和必要密钥更新由相应权限人员处理。

    变更后补齐受影响配置与测试，再做当前版本全网体检，另存交付记录；详细步骤见[变更与重新验证](/platform/deployment#变更与重新验证)。

  </Accordion>
</AccordionGroup>

### 调试验证

在**功能验证**中核对测试对象、实际具备的功能及期望配置版本，再**保存验证计划**。

正常功能验证开始前，回路内全部设备或被单独测试的设备须已绑定、配置已同步且在线；离线、状态未知或被现场复位时先处理。按本次设计的能力测试，缺少设备、接口或执行条件时保留待验证，不强行写成通过。

| 对象 | 最必要的验证 |
| --- | --- |
| **照明回路组** | 实际开关、调光下限、走动响应与控制照度；覆盖组内控制器和供电已确认的传感器。开关型不做中间亮度调光测试。 |
| **单独设备** | 未被回路测试覆盖的占用、照度与环境指标；温控器设定、实际状态与反馈，分别保留逐设备结果。 |
| **系统接入与计量** | 当前连接版本的连接、数据、控制与应用验证；核对地址、对象、单位、倍率和总分表边界。纯只读来源的控制验证为“不适用”。 |
| **场景、定时与联动** | 仅测试已纳入设计且具备执行条件的任务，核对来源、目标、项目时区、时间条件及实际动作，检查各对象结果。 |
| **断联与恢复** | 分别测试云端不可用、网关断联、传感缺数及重新供电后的真实行为。设备本地与原厂保护不能依赖云端持续在线。 |

照度读数、当前亮度与真实照明效果分别核对；温度设定与室温、控制提交与实际运行分别核对；环境缺测不写正常，表计缺数不记零。不要以界面值改变代替物理动作和回读。

测试记录须写明设备身份、覆盖对象、测试项目、结果、测试时的期望配置版本、执行人与时间。设备期望配置变化、现场复位、替换硬件或覆盖不完整时，补齐后重新测试；旧版本通过不能作为当前版本通过。详细方法见[测试与验证](/platform/deployment#功能验证与全网体检)。

### 完整网络体检

回到 Station 的设备网络执行**全网体检**：网关须已绑定且在线，参与设备配置全部同步，且没有固件升级、密钥更新或其他体检冲突。

检查完整网络、当前网络版本和逐台结果，要求每个节点都有应答、到达率达到当前网络模板的通过标准，并核对时延、跳数及异常位置。先排查网关附近和局部问题，调整后在当前版本复测全网。

小范围体检用于排查，不能代替交付全网结果；待绑定或被现场复位的设备不参与体检，也不因此免除补绑与验证。共享网络按全部服务范围核对，缩小所选楼层或本次部署范围不能跳过网络其他成员。

## 整理交付记录

在**配置进度 › 验证与交付**核对整个设备网络的五项结果，缺项先处理：

- 本网络网关与全部 Mesh 点位对应的设备已绑定。
- 当前期望配置全部同步，无影响同步的现场改动**待并入**。
- 当前配置版本的功能验证有效，每台设备有明确覆盖依据。
- 最近一次当前网络版本的全网体检通过。
- 安全待办完成，已移除、拆走或丢失设备所需密钥更新取得真实结果。

随后按**检查 → 核对代理 → 安全处理 → 确认存档**完成交付，由机构管理员点击**确认并存档**。代理交付后保留常开，数量及角色建议是核对提示，不另设阻止交付条件。没有必需安全待办时，可按项目要求选择是否在交付时更新密钥；已有待办不能留到运营阶段。

交付快照冻结当时的网络与服务楼层、图纸、设备身份及绑定、固件与期望配置、测试、体检和批准依据。后续影响设备期望配置或网络版本的变更另存交付，不覆盖旧记录。新增批准参数仍待生成到网络配置时，旧交付不覆盖；批准范围内的照明运营调整另按平台规则处理。

第三方系统的连接、数据、控制与应用结果另行保留，设备网络交付不能代替这些验证。具体步骤见[确认交付并转交运营](/platform/deployment#交付与运营交接)。

| 交给运营与维护人员 | 需要说清楚 |
| --- | --- |
| **现状资料** | 已安装位置、接线与供电关系、交付网络、全部服务楼层、设备及配置版本；更新后的图纸与清单。 |
| **验证记录** | 测试覆盖、未通过与不适用项目、全网体检、批准和安全处理结果，以及哪些内容不在交付范围。 |
| **使用条件** | 可操作对象、批准的可调范围、工作时间、现场手动方式和断联条件；普通成员从“我的区域”进入授权功能区。 |
| **后续安排** | 遗留问题、未结束检修、未恢复告警与待完成工单，注明负责人、完成安排和维护联系人。 |

交接时用一个典型空间演示查看、操作、核对结果和反馈问题，确认运营人员知道何时联系配置人员或机构管理员。安装完成、整网交付与后续运行正常仍是不同结果，运行状态和告警需持续检查。

现场实施的详细操作见[部署与交付](/platform/deployment)，空间与设备对应见[项目与空间](/platform/projects)和[设备与网络](/platform/devices)，日常使用从[智能建筑用户指南](/guides/user)和[总览](/platform/runtime)开始。
