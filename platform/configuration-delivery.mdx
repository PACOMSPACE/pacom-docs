面向集成商、配置人员与机构管理员。规划资料准备后，在 Station 完成应用配置与批准，通过独立部署 App 实施现场工作，再回到 Station 核对测试、全网体检和交付记录。

**期望配置**指对应设备需要应用的目标配置及版本，用于与现场实际结果核对。

**保存记录、批准参数、设备应用、测试通过与确认交付，各有自己的完成依据。** 以下说明配置与交付方法；实际操作须以所用版本可用的执行服务、真实设备回执和现场记录为准，演示结果不能作为验收证据。

## 确认范围与配置进度

打开**配置进度**，选择项目、本次部署楼层与启用功能，按空间资料、设备、系统接入、应用配置、验证与交付查看待办。具体修改从待办进入对应对象。

- **确认范围**：本次启用的应用决定接入与配置检查；跨应用项始终核对。项目统计与本次范围分别查看，不把全项目数量当作本次完成数量。
- **确认规划**：图纸、点位、供电与控制关系、网络范围和系统接入资料应相互对应，前置准备见[项目与设备](/platform/projects-devices)。
- **确认人员**：机构管理员或获项目授权的配置人员可配置并使用部署 App；参数批准与交付确认仅由机构管理员完成。
- **确认验收要求**：约定需要测试的对象、动作、数据、断联条件，以及运营交接范围和遗留事项的处理方式。

与本次楼层相交的共享设备网络，体检与交付仍按**整个网络**判定。缩小楼层范围不能跳过其他网络成员。

## 应用配置

从**配置进度 › 应用配置**进入应用设置与**配置参数**。先核对项目采用的规范、空间用途、型号与固件能力、参数模板及作用范围，再确定具体值。

配置参数按 **项目 → 楼宇 → 楼层 → 功能区**继承。为下级覆盖时写明范围、值与原因；删除覆盖后恢复上级继承。项目不会自动采用新模板，模板更新由机构管理员核对并采用，再检查保留值及待批准项。

<AccordionGroup>
  <Accordion title="照明" description="先确认回路与传感关系，再设定控制行为。">
    - 核对开灯策略、**占用三段**、有人亮度、恒照度目标、手动后恢复自动，以及时间安排和失联回退。占用三段说明无人后的延时、待机亮度与时长、结束动作。
    - 逐回路核对开关型或调光型、驱动下限及真实负载。开关型设备不能执行中间百分比调光。
    - 需要恒照度控制的回路组，确认唯一且有效的控制照度源；分别核对占用、额外跟随占用与诊断照度来源。
    - **照明控制参数**区分楼层默认与功能区覆盖；可调范围取机构管理员批准的配置参数。保存后仍要核对对应控制器的同步结果。

    测试时对照实际动作、调光下限、走动响应与照度读数，不只看界面值已改变。
  </Accordion>

  <Accordion title="暖通空调" description="按风机盘管、多联机与只计量的分体空调分别核对。">
    - **风机盘管**：核对水系统、设定范围、待机与节能、面板锁、防冻、断电恢复和通信中断策略。季节计划不能代替现场冷热源条件。
    - **多联机**：核对内外机对应关系、可写范围、无人策略、写入限制与原厂保护。待机、节能策略不直接套用于多联机。
    - 多联机逐外机核对原厂限温、线控器禁止项、模式、来电自启和设定步长。需要在原厂控制器完成的设置，现场设置后登记确认，平台不代替原厂设置。
    - **分体空调**仅计量用电，不作为平台控制对象。中央系统的可写点须先通过控制验证。

    **暖通空调设置**选择适用楼层并查看当前值；保护、限温与回退等配置在**配置参数**中逐项核对。
  </Accordion>

  <Accordion title="室内环境" description="确认测量能力、采集代表性与统计条件。">
    - 按真实器件与接入能力确认温湿度、CO₂、PM2.5 等指标、单位、数据来源与更新时间。
    - 为各空气质量传感器登记采集位置，以及读数代表整个功能区、局部还是尚待核对。
    - 参考范围、统计窗口、告警进入与解除、缺测处理在**配置参数**中核对；**室内环境设置**不另填一套阈值。
    - 需要校准或能力验证时，保存对象、方法和结果。缺失数据保留缺测状态，不能按零值或正常值处理。

    瞬时读数、统计均值与告警结论的时间条件不同，测试和运营交接时分别说明。
  </Accordion>

  <Accordion title="能源与碳排放" description="先明确计量边界，再核对费用、基线与排放口径。">
    - **能耗设置**选择已登记的计量来源，核对总表、分表、所属总表、覆盖楼层与计入方式，避免总分表重复计入总量。可以先保存设置，数据验证通过后才用于用电统计。
    - 倍率、起始底数等来自**系统接入 › 数据映射**；能耗设置登记计量边界、折标系数、基线与计费方式，不重复登记原始点表。
    - 费用按正式供电资料及生效时间登记；费用结果是估算。节能基线须满足有效历史计量数据及相应模型条件。
    - **碳排放设置**登记 CO₂ 或 CO₂e 口径、因子与单位、年份、地区、来源、用途、有效区间及核算边界。没有适用因子的日期不套参考因子。
    - 启用需量限制前，须登记现场测试记录并由机构管理员批准相应参数；地方能耗平台的**对外上传**设置仅由机构管理员登记，上传结果以接收平台回执为准。

    能耗、碳排放设置保存形成各自版本。排放因子、折标系数和电价在配置参数中只读引用对应设置，不重复修改或批准。
  </Accordion>
</AccordionGroup>

**跨应用条件一起核对**：项目时区、工作时间与节假日表、室外温湿度来源、时间同步、执行位置、动作优先级、通信中断及保护边界。工作时间与节假日表在**场景 › 定时**中登记，室外来源在**系统接入**中核对；控制策略不能替代设备本地或原厂保护。

## 配置批准与生效

配置人员提交的**适用规范登记**需机构管理员批准；机构管理员保存登记直接生效。应用设置保存形成版本，配置参数值与下级覆盖则按参数批准规则处理。

<Steps>
  <Step title="核对并保存修改">
    核对配置项、完整范围、目标值、单位、依据与执行位置。修改参数或下级覆盖时填写变更原因；已批准值改变后，回到**待批准**。
  </Step>
  <Step title="补齐能力与测试依据">
    对**待验证**项核对型号、固件及测试要求，登记测试编号、方法、对象、结果和值与版本。未通过或结果待确认不能标为已验证；参数测试记录也不代替设备应用回执。
  </Step>
  <Step title="由机构管理员批准">
    管理员逐项或通过**批准所选**核对具体值、完整范围、参数版本、依据与能力条件。提交时内容或版本变化，应重新审阅后批准。
  </Step>
  <Step title="核对期望配置与现场应用">
    查看**下发包预览**及未进入的项目和原因，再核对设备期望配置版本与逐台应用回执。预览和批准都不等于已发送到现场。
  </Step>
</Steps>

| 状态或资料 | 如何判断 |
| --- | --- |
| **待批准 / 已批准** | 是否已允许相应参数执行；不能据此判断现场生效。 |
| **待验证 / 已验证** | 能力或测试依据是否有效；已验证须关联对应对象、值与版本的测试记录。 |
| **待核对** | 仍有资料或条件需确认，按该项说明处理。 |
| **配置同步** | 对应设备是否有真实的应用成功回执，且匹配当前期望配置版本。 |
| **平台规定 / 引用设置** | 平台规定只读；引用设置返回对应应用设置修改，不在参数表重复批准。 |

若提示**待生成到网络配置**，说明批准参数尚未生成到设备的期望配置。须待相应服务生成、下发并核对回执后继续验证；已有交付不能覆盖这些新增批准项。

## 准备现场实施

在设备网络中打开**准备现场绑定**，核对网络与规划版本、服务楼层、网关状态、待绑定点位和可部署成员。

- **保存规划**：有未保存修改时先保存并检查，现场资料应与已保存版本一致。
- **处理阻止项**：按检查说明处理阻止项；比例尺、角色建议等提示与阻止项分开。空间资料缺项本身不阻止实际绑定。
- **准备安装资料**：导出同一规划版本的 PDF 现场安装图与 Excel 设备清单，用于布线与安装；规划变化后重新生成。
- **核对现场条件**：网关供电与联网、实际位置、接线与负载、设备型号及施工条件，与规划不符时先核对调整。
- **确认账户**：部署人员用本人账户登录 App，具备本项目部署权限；首次打开网络需联网下载资料。
- **核对许可与用量**：确认机构订阅状态与可用设备额度。未订阅或额度已满时，新设备无法绑定或接入，由机构管理员处理。

现场安装资料不含设备身份与网络密钥，也不证明绑定、配置应用、测试或交付完成。现场绑定使用 App 按权限取得的**网络资料**。

## Station 与部署 App 的交接

**Station 管理规划、期望配置、全网体检与交付；部署 App 完成现场身份确认、绑定、配置和局部测试。** App 凭账户与项目权限打开网络并下载资料。

<Steps>
  <Step title="先绑定网关并建立网络">
    按规划位置连接实际网关，配置有线或无线联网，再建立网络。网关绑定由实际部署服务确认；只有网关已绑定的网络才能继续绑定成员设备。
  </Step>
  <Step title="打开网络，按回路绑定设备">
    App 下载该网络全部服务楼层的资料，核对网络版本、图纸与点位。从网关附近开始，由近及远、按回路对应实际设备身份；跨楼层网络逐层核对。
  </Step>
  <Step title="核对配置、首次上报与局部测试">
    逐台核对期望配置版本、实际应用结果与首次数据上报。App 按回路组或单独设备做现场测试，记录实际动作和未通过项目。
  </Step>
  <Step title="上传记录，回到 Station 核对">
    将绑定回执、配置结果、测试记录和现场改动上传。Station 核对同步与功能验证，再安排当前版本的全网体检和交付。
  </Step>
</Steps>

<AccordionGroup>
  <Accordion title="现场改动：以现场实际值为准" description="上传依据与结果，再核对能否并入当前规划。">
    改供电、驱动或回路组时，记录原依据、现场值、网络版本、已执行对象和提交信息。驱动或负载登记可能只改变规划资料，不能统一当作硬件已执行。

    - 能落入当前规划的现场值并入 Station，形成新的网络版本，按影响补齐配置并重新测试。
    - 无法落入当前规划时保留**待并入**；相关设备不能按平台规划覆盖下发，也不能按已同步进入交付。
    - 先按现场调整规划，再完成并入。核对哪些设备已有有效回执、哪些仍需补配置或重测。

    现场回执尚未上传或结果未确认时，先核对原请求和实际状态，避免重复执行。
  </Accordion>

  <Accordion title="增补设备：下载新资料，补绑并重新验证" description="已有网络无需重复首次网关绑定。">
    保存新增点位形成新的网络版本后，在 App 打开原网络，联网同步变化的点位配置与图纸。按回路补绑，核对配置和局部测试，再回 Station 做当前版本全网体检并另存交付。

    交付后的各层代理保持常开，供 App 现场连接。App 采用平台已采纳的中继与代理规划，不能把自动建议当作已执行的角色配置。
  </Accordion>
</AccordionGroup>

## 测试与验证

先保存验证计划，核对需要覆盖的设备、实际具备的功能和期望配置版本。**在线、已绑定或同回路其他设备通过，都不能代替该设备的有效测试记录。**

### 功能测试

| 对象 | 主要核对 |
| --- | --- |
| **照明回路组** | 按实际能力测试开关、调光下限、走动响应与照度源读数；覆盖组内控制器及已确认供电的传感器。 |
| **单独设备** | 温控器的设定与状态反馈、空气质量传感器的实际指标、未并入回路测试的占用与照度上报。 |
| **系统接入** | 分别验证连接、数据、控制及应用；纯只读来源的控制验证为“不适用”，见[系统接入](/platform/projects-devices#系统接入)。 |

回执应点名测试对象和覆盖设备，并保留测试项目、结果、测试时的期望配置版本、执行人与时间。配置变化、现场复位或回路覆盖不完整时，按提示补齐配置并重新测试；旧版本通过不能作为当前版本通过。

### 全网体检

在 Station 的设备网络中执行全网体检，核对当前版本的通信质量。

1. **先核对前提**：网关已绑定并在线，参与的已绑定设备配置全部同步；没有正在进行的固件升级、密钥更新或其他体检。
2. **检查完整网络**：记录参与范围和网络版本，每个节点均应答，到达率达到当前网络模板的通过标准，并查看逐台时延与跳数。
3. **处理异常后复测**：核对离线、配置不同步或连通问题，调整后在当前版本完成全网体检。

小范围体检用于排查，不能代替交付所需的全网结果。待绑定或被现场复位的设备不参与体检，也不因此免除交付前的绑定与验证要求。

## 确认交付并转交运营

在**配置进度 › 验证与交付**核对整个设备网络。以下五项由系统按当前对象与版本判定，缺项须先处理：

- 本网络网关与设备已绑定。
- 当前版本配置全部同步，无待并入的现场改动影响同步。
- 当前期望配置版本的功能验证记录有效，并覆盖相应设备。
- 最近一次当前网络版本的全网体检通过。
- 安全待办已处理；已移除、拆走或丢失设备所需的密钥更新不能留待交付后跳过。

随后核对各层代理、按实际需要完成安全处理，再由**机构管理员确认并存档**。代理交付后保留常开；代理数量或角色建议是核对提示，不额外作为阻止交付条件。

安全要求高的客户可选择交付时更新密钥；已有必须处理的安全待办则先完成。安全结果以真实服务回执为准，不能用选择了处理方式代替处理完成。

交付记录冻结当时的网络与服务楼层、图纸、设备身份与绑定、固件与期望配置、功能测试、全网体检及参数批准值与依据。历史快照只读，不用当前资料回填缺失字段。

<AccordionGroup>
  <Accordion title="交付后的变更怎样处理" description="区分工程变更与批准范围内的运营调整。">
    - **设备或网络变更**：新增设备、修改网络参数或影响配置的变更形成新版本，按影响补齐同步、测试与全网体检，再另存交付记录。
    - **新增批准参数**：若仍待生成到网络配置，旧交付不覆盖这些参数；生成并核对真实回执后重新验证与交付。
    - **照明运营调整**：在已批准可调范围内修改照明控制参数，不改变设备期望配置版本，不使功能验证失效，也不需重新交付；仍要核对同步结果。
    - **缩短占用刷新**：属于网络变更，由配置人员或机构管理员确认保存，不能当作普通运营调整。

    当前版本没有新变更时无需重复交付；详细变更处理见[告警与维护](/platform/alarms-maintenance#变更与重新验证)。
  </Accordion>
</AccordionGroup>

向运营人员交接：

- 空间与设备资料、交付范围、配置版本和测试记录。
- 可操作对象、批准的可调范围、时间安排及断联时的使用条件。
- 未包含在交付范围内的事项、遗留问题、责任人与维护联系人。

交接后从[日常运营](/platform/operations)开始。交付是对应版本的验收记录，后续运行状态与告警仍需持续核对。
