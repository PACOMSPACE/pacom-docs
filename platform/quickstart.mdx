先选择正确的机构与授权范围，再判断项目处于规划、现场实施还是日常运行阶段。新项目与已交付项目采用不同的开始路径。

<Note>
  当前账户、运行数据与执行服务尚未全面接入。以下访问、邀请与操作以正式服务回执为准；申请、浏览器记录或演示结果不能证明机构已开通、权限已授予或设备已执行。
</Note>

## 登录与机构入口

收到成员邀请后，使用邀请指定的邮箱创建账户，或用该邮箱的已有账户登录后接受邀请，不重复注册。验证绑定的手机也可登录；申请资料中的联系电话不会自动成为登录方式。

登录后核对机构名称、本人角色与授权范围。多个机构分别授予权限，从左下角**机构菜单**切换；没有机构时，联系机构管理员发送邀请，或为新机构**申请访问**。普通成员进入**我的区域**，其他角色从**总览**进入工作；没有所需项目或功能区时联系机构管理员。

同一单位的其他园区或楼宇在当前机构中创建项目；为另一家单位申请**开通新机构**时，由 PACOM 审核，数据隔离且不继承当前机构的权限。账户、安全与邀请细节见[我的账户](/platform/account)和[机构设置](/platform/organization)。

## 起步路径

<Steps>
  <Step title="获得访问并确认机构">

    新机构在登录页点击**申请访问**，由申请人提交资料，经 PACOM 审核后通过邮件获得开通邀请；已有机构成员通过邀请加入，不必再申请新机构。申请已提交不等于机构已开通；结果未知时先**核查提交结果**，不要重复提交。申请与邀请以正式服务确认的结果为准，具体步骤见[机构设置](/platform/organization)。

    登录后确认机构名称、本人角色和授权范围。没有所需项目或功能区时，联系机构管理员。

  </Step>
  <Step title="确认项目处于哪个阶段">

    新项目先准备图纸、空间用途、设备与系统清单、工作时间和实施目标。已有项目先核对已交付网络、配置版本、运行数据来源与更新时间。

  </Step>
  <Step title="按职责进入工作">

    - **机构管理员**：在[机构设置](/platform/organization)核对成员与授权，明确配置批准和交付责任。
    - **配置人员 / 集成商**：从[项目管理](/platform/projects)建立空间、规划设备，再按[部署调试](/platform/deployment)完成部署、测试与交付。
    - **运营人员**：从[运行总览](/platform/runtime)选择已交付范围，核对数据质量，再处理控制、场景与告警任务。
    - **查看人员**：查看授权项目的运行与分析资料，不执行控制或修改配置。
    - **普通成员**：从**我的区域**进入授权功能区，查看和控制自己的灯光、空调；不进入项目配置或场景管理。

    集成商不是独立的系统角色，实际操作范围由所在机构授予的角色与项目范围决定。需要接口对接时，另查[开发文档](/developers/index)。

  </Step>
</Steps>

## 使用条件

沿以下状态逐项核对，不用一个“完成”代替所有结果。

| 状态 | 依据 |
| --- | --- |
| **已保存** | 平台中有当前规划或配置资料。 |
| **已批准** | 需批准的配置参数已获机构管理员批准；仍需核对期望配置与现场应用。 |
| **已绑定 / 已接入** | 核对真实设备身份与相应回执；设备网络中的绑定与系统接入分别确认。 |
| **设备已应用** | 现场设备返回与当前期望配置版本匹配的成功应用回执。 |
| **在线** | 有有效通信记录，并核对最近更新时间。 |
| **已验证** | 功能、实际负载及必要的断联恢复测试通过，保留对应设备与配置版本的记录。 |
| **已交付** | 按完整网络范围核对版本与测试证据，完成交付确认并保留记录。 |

在线不等于功能已验证；部分房间通过测试不等于整个网络已交付。控制结果未知时先查询原请求和实际状态，避免重复下发。

建设项目从[项目管理](/platform/projects)与[设备管理](/platform/devices)开始；现场实施查[部署调试](/platform/deployment)，已交付项目查[运行总览](/platform/runtime)。普通成员的日常步骤见[智能建筑用户指南](/guides/user)。
