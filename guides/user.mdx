面向空间使用者和物业运营人员，说明在 **PACOM Station** 中查看状态、控制照明与空调、执行场景和反馈问题的方法。现场温控器与墙面开关的操作，查阅对应型号的用户资料。

<Note>
  当前身份、运行数据与硬件控制服务尚未全面接通。以下操作用于相应服务和设备接入并验证后的项目；实际状态、下发与生效以服务回执和设备回读为准，演示值不能作为现场结果。
</Note>

## 日常使用

### 确认使用对象

登录后先核对左下角的**机构与角色**。同一账户在不同机构的角色和授权分别授予；切换机构后，重新确认正在使用的空间。

| 使用者 | 从哪里开始 |
| --- | --- |
| **普通成员**：租户、部门负责人等 | **我的区域**，点击获授权的功能区，查看和控制照明、空调，查看室内环境。 |
| **运营人员**：物业、值班与设施管理人员 | **总览**，选择项目、楼宇或楼层，再打开功能区；需要批量安排时进入**场景**。 |
| **查看人员** | 在授权项目中查看状态，不控制设备或执行场景。 |

普通成员没有总览五个页签、场景、告警、搜索和智能助手入口。公共区域由运营人员管理；并非每位现场使用者都需要账户。邀请、角色和区域授权由机构管理员处理，见[成员与权限](/platform/organization#角色与权限)。

### 准备操作条件

<Steps>
  <Step title="找到正确空间">

    普通成员在**我的区域**核对项目、楼宇、楼层和功能区名称，再点区域卡片。运营人员在**总览**选定位置，从楼层图或功能区列表打开。手机先打开菜单，进入相同入口。

  </Step>
  <Step title="查看当前状态">

    先看**数据截至**、当前开关与设定、自动或手动状态，再决定是否操作。「尚未取得运行数据」「状态未知」和「—」都不能当作关闭、零值或正常；超过 5 分钟没有新数据时，变暗的旧数值不能当作当前值，按页面提示重试。

  </Step>
  <Step title="核对范围和权限">

    操作前核对确认中的对象、动作、全部目标、当前离线设备和有效期。一个按钮可能影响多个设备或区域，不只影响屏幕上正在查看的房间。

    普通成员只有在设备的全部服务功能区都获授权时才能控制；跨区回路组涉及的区域须全部授权。按钮不可用时先读原因，不用反复点击或换入口绕过限制。

  </Step>
</Steps>

日常先看本区照明、空调与室内环境。**有人 / 无人**表示占用状态，不是人数；无在线占用来源时按**未知**理解。查看空气质量时保留指标、单位和更新时间，一处传感器的读数不代表整栋建筑；持续异常交给运营人员核查。

运营人员还可在**总览 › 概况**查看**需要处理**，从对应入口处理告警与设备问题；环境、能源和大屏的详细用法见[运行总览](/platform/runtime)。

## 照明控制

在功能区面板打开**照明**，查看当前开关、亮度及自动或手动状态。先选择动作，在**确认控制**中核对目标与影响，再点**确认下发**。

| 想完成的任务 | 操作与后续行为 |
| --- | --- |
| 临时开灯或关灯 | 点击**开灯 / 关灯**。原来是自动时仍保持自动；原来是手动时仍为手动，并重新计时。 |
| 调整亮度 | 拖动亮度滑块或选择**调光**，核对**目标亮度（%）**。生效后进入手动；开关型回路不能调到中间亮度。 |
| 结束手动照明 | 点击**恢复自动**，交回本区已有感应和照度规则；不保证立即开灯或恢复到某个固定亮度。 |

调光后查看**将在 HH:MM 恢复自动**。照明按本区的**手动后恢复自动**时长，或作用于本区的下一次有效定时执行，先到者恢复；工作时间与非工作时间可不同，不统一按“两个小时”理解。

**在自动状态下人为关灯后，本区须出现一次“无人”，才会再次感应开灯。** 仍有人时没有重新开灯，可能是正常规则。调光进入手动后，感应或恒照度也不会立即覆盖新的手动亮度。

亮度滑块松开只是选择目标；以设备确认后的开关、亮度和模式判断结果。运营人员调整延时、有人亮度等长期行为时使用**照明控制参数**，不要用反复手动调光代替参数设置，详见[照明控制](/platform/lighting#查看照明)。

## 空调控制

在功能区面板打开**暖通空调**，先辨认风机盘管、多联机内机或**只计量**的分体空调。只有已接入并验证可写的对象才提供控制；只计量对象不能从平台开关或调温。

<Steps>
  <Step title="选择动作">

    使用**开启、关闭**，或在设定值旁点击 **− / +** 调温。在**确认控制**中核对**运行模式**、**设定温度**（℃）及设备范围；可选模式、温度范围和步长按当前季节、机型与空间设置提供。

    多台设备共同调温时，只能选择各台都能设置的值。热泵多联机改变冷热模式可能影响同一冷媒系统的其他区域；普通成员须拥有这套系统全部服务功能区的授权才能改模式。当前网页显示风速状态，不提供改风速操作。

  </Step>
  <Step title="确认有效期并下发">

    先读**有效期**与控制关系，再点**确认下发**。工作时间手动开机或调温保持到下一次时间表开关机，或执行**上班 / 恢复自动**。

    加班等非工作时间开机，核对确认中显示的结束时间。有效期内不会因无人转入待机、节能；到期已进入开机时段则交回时间表，否则关闭。

  </Step>
  <Step title="检查回读，需要时恢复自动">

    核对设备回读的开关、模式和设定值。结束临时操作时用**恢复自动**交回现有时间表及相应占用规则，不保证立即开启空调。

  </Step>
</Steps>

**手动关闭空调**保持到下一次时间表开机（含预启动），或执行**上班 / 恢复自动**才解除。有人、其他场景或需求响应不会重新开机；如果希望重新按自动规则运行，使用恢复自动，不要等待感应开机。

调温成功不代表室温立即达到设定。楼层或功能区室温来自多功能传感器；风机盘管用内置传感器温控，多联机用回风温度。多联机显示**温控开**只表示原厂温控需求，不等于压缩机已经运转。

风机盘管处于待机或节能时，调温改变的是**舒适设定**，检测到有人后按新设定恢复；出现保护或可调范围限制时先核对原因。更完整的系统差异与控制规则见[暖通空调](/platform/hvac#查看空调)。

## 场景操作

本节供有项目授权的运营人员、配置人员和机构管理员使用。普通成员从功能区面板操作，不管理场景或定时。

<Steps>
  <Step title="选择已有场景">

    打开**场景 › 场景**，选定项目与位置，核对场景的动作、范围、当前版本和**同步**状态。点击场景行查看详情；行末**执行**用于开始执行。

  </Step>
  <Step title="确认影响再执行">

    点击**执行**，展开核对全部目标、在线与离线设备，以及覆盖现有手动操作的影响，再点**执行场景**。含照明与空调动作时，先下发空调，两类结果分别回报。

    当前照明场景使用本项目只含 LC20 照明控制器的控制分组；空调动作作用于这些控制器所在功能区的风机盘管与多联机内机，不是任意选取空调。豁免空间的空调不受场景动作影响。

  </Step>
  <Step title="查看本次执行结果">

    在行内或**场景 › 执行记录**核对时间、触发方式、执行版本与逐网络结果。保存或同步场景不等于已经执行；有回执后再判断各目标是否生效。

  </Step>
</Steps>

**上班**使照明和空调恢复自动；**下班**关灯并保持自动，关闭空调，但不会提前结束仍有效的非工作时间手动开机。执行前仍须确认范围与设备状态，不把场景名称当作整栋建筑都已完成操作的证明。

需要固定时间执行时，在**场景 › 定时**核对**工作时间、节假日表、项目时区**及下次执行。未登记当年节假日表时，“工作日”按周一至周五，法定节假日不会自动跳过；按通知填入后仍须保存。暂停用**停用**，跳过个别日期用**例外日期**；停用的定时不会再结束已有手动控制，需要立即交回规则时用恢复自动。

完整创建定时、联动及跨午夜规则见[场景](/platform/scenes#创建场景)。普通同区“有人开灯、无人关灯”和恒照度由照明控制器本地处理，不需再建重复联动。

## 检查操作结果

**已下发**表示命令已发出；**已生效**须有设备回执与状态回读。目标值、服务受理和实际状态是不同结果，不能只看成功提示或按钮变化。

| 看到的结果 | 下一步 |
| --- | --- |
| 单台**等待确认 / 未确认** | 单台 5 秒未确认时，先查看原操作记录、设备回读与现场状态，不连续重发。需要重试时重新核对确认内容。 |
| 组控制**未回报 N 台** | 约 45 秒仍未回报时用**重新查询**，查看具体设备与最后数据时间。未回报不等于未执行或失败。 |
| **已生效 N / M、部分成功** | 找出剩余对象及原因，已生效设备不重复下发。普通控制的失败重试只针对已确认失败项；场景未回报按下文的记录入口处理。 |
| 设备**离线**或网关离线、**状态未知** | 核对最后数据时间及通信情况。网关离线不代表所有设备都离线，不用最后读数推断当前状态。 |

平台手动控制查**总览 › 操作记录**；普通成员可从**确认控制 › 查看操作记录**查看授权区域的控制。场景、定时与联动查**场景 › 执行记录**。保留执行时的版本、目标与结果，避免把后续修改后的场景当作原执行内容。

执行记录出现**重试 N 台**时，先重新查询并核对原结果。重试只针对原未回报中、当前在线且仍在原场景目标内的 LC20；重新确认版本与权限，已生效的不再下发。场景已改版或删除时，不能直接沿用旧记录重试。

## 常见问题

<AccordionGroup>
  <Accordion title="无法登录，或找不到需要的区域">

    先核对当前机构与角色、受邀邮箱和区域授权。普通成员没有获授权区域，或原区域已删除时，联系机构管理员；新建或拆分的功能区不会自动加入旧授权。公共区域由运营人员管理，不通过给普通成员开权限处理。

    忘记密码用登录页**忘记密码？**；手机只有验证绑定后才能登录，申请资料中的联系电话不会自动成为登录方式。

  </Accordion>
  <Accordion title="控制按钮不可用，为什么只能查看">

    阅读按钮下方原因，依次核对角色、全部服务区域授权、运行数据、网关与设备在线、当前可写能力和保护。只有计量数据的空调不能控制；一个回路服务未授权区域时，也不能只控制其中一个房间。权限问题联系机构管理员，连接或设备问题联系运营人员。

  </Accordion>
  <Accordion title="关灯后没有再感应开灯，或灯光一直保持手动">

    自动状态人为关灯后须先出现一次无人；手动调光则核对恢复时间及下一次有效定时。想立即结束手动用**恢复自动**。仍异常时，由运营人员检查占用来源、传感器供电与遮挡、控制回路和配置同步，见[照明控制](/platform/lighting#查看照明)。

  </Accordion>
  <Accordion title="空调没有按调温预期运行">

    先对照设定与回读，再检查当前模式、可调范围和保护。待机或节能中的调温改的是舒适设定；手动关闭不会被有人触发解除。恢复自动后，仍按已有时间表运行。不要把房间测温、多联机温控开或计量功率当作压缩机实际运行证明。

  </Accordion>
  <Accordion title="定时没执行，或者执行时间不对">

    由运营人员核对项目时区、工作时间、当年节假日表、例外日期、启用状态、当前版本同步和执行记录。项目时区未设置时明确按 UTC 显示，不按手机时区猜测。保存任务不是网关已接收的证明；改变工作时间也会影响按工作时间执行的定时。

  </Accordion>
  <Accordion title="网络中断后，还能自动运行吗">

    先区分手机网络、平台连接、网关离线和现场设备断联。已应用并经现场验证的本地自动控制、定时和同网络联动可在对应条件下继续；跨网络与跨系统任务的受影响部分不能据此保证执行。运营人员核对实际记录与现场状态，普通成员不要反复远程下发。

  </Accordion>
  <Accordion title="数据不更新，或看到环境、设备异常">

    查看**数据截至**和最后上报时间，按提示重试；缺数不等于零，也不自动等于设备故障。普通成员记录区域、时间与现象后联系运营人员；运营人员核对来源和持续时间，再进入[告警](/platform/alarms)。不要用旧读数判断当前正常。

  </Accordion>
</AccordionGroup>

## 整理问题反馈

权限、区域归属和日常操作问题，先联系本机构管理员或运营人员；无法解决时，使用**机构菜单 › 帮助 › 联系支持**。无法登录时，从账户页**联系我们**取得支持邮箱。

<Steps>
  <Step title="写清问题与结果">

    在**问题说明**写明页面、位置与对象、发生时间、做过的动作、预期和实际结果，补充重现步骤及已做检查。帮助页中的**软件版本**会列入复制内容；设备问题按需准备点位名称、序列号、固件与配置版本及相关回执，不必收集所有编号。

  </Step>
  <Step title="核对附带内容">

    **当前对象、日志、截图**均可选，默认不附带。只选排查所需内容，检查并移除密码、短信验证码、密钥、个人信息及无关客户资料；页面不会自动截图或保证脱敏。页面日志不是完整设备日志或服务端审计。

  </Step>
  <Step title="复制并发送邮件">

    点击**复制内容**，将文本粘贴到发给 [support@pacom.cn](mailto:support@pacom.cn) 的邮件中；选择的截图另作为邮件附件添加。当前帮助页不能直接提交或上传，**已复制**不代表已发送或受理。保留邮件往来与支持回复，便于跟进。

  </Step>
</Steps>
