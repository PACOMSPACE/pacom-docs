面向运营人员、机构管理员与使用空间的成员。从已交付、已接入运行数据的范围开始，先看状态与数据质量，再操作设备或安排自动任务。

实际可用的指标、控制与自动任务取决于项目接入和当前版本的服务。提示**尚未取得运行数据**或**执行服务尚未接入**时，不能把规划、草稿或演示结果作为现场状态和执行依据。

## 日常查看与操作

<Steps>
  <Step title="选择范围">
    打开**总览**，确认机构并选择项目、楼宇或楼层。楼层查看状态图；楼宇及以上查看下一级对比表，统计只包含已接入运行数据的楼层。

    普通成员从**我的区域**打开获授权的功能区，查看照明、空调与室内环境，并按权限控制照明和空调；不使用总览五页签、能源、场景、告警或大屏。查看人员只能查看。
  </Step>
  <Step title="先看需要处理的事项">
    在**概况**查看未恢复告警、设备在线率、今日用电和环境正常的空间，再检查**需要处理**。点击功能区查看详情；告警从对应条目或图上角标进入[告警与维护](/platform/alarms-maintenance)。

    核对**数据截至**、覆盖范围与数据质量。总览、告警、场景有运行数据时每分钟更新；超过 5 分钟未取得新数据会提示重试，变暗的旧数值不能当作当前值。
  </Step>
  <Step title="确认对象后操作">
    有控制权限时，从功能区或单台设备进入操作。整层或多对象控制前，核对实际设备、服务功能区、动作、离线情况和有效时间，再确认下发。

    普通成员只能控制服务功能区全部在授权内的设备；跨功能区回路组须覆盖全部相关区域。权限与授权问题见[机构与账户](/platform/organization-account#成员与权限)。
  </Step>
  <Step title="核对回读与记录">
    提交、受理与生效分别核对，以设备实际回报为准。平台控制查看总览的**操作记录**；场景、定时与联动查看**场景 › 执行记录**。批量操作逐对象或逐网络核对，不能用总体提示代替完整结果。
  </Step>
</Steps>

### 判断结果

| 看到的状态 | 下一步 |
| --- | --- |
| **所选范围没有运行数据** | 核对接入范围，切换到已接入的楼层；缺数不等于零值或正常。 |
| **网关离线 / 状态未知** | 先检查网关与通信；不能据此把所有下级设备都判为离线。 |
| **等待回报 / 未回报** | 先重新查询原请求与现场状态。未回报不等于未执行，不应直接重复下发。 |
| **已生效 N/M / 部分成功** | 定位未完成对象及原因，处理后重新核对范围与权限，再按需重试。 |

没有传感器时，占用或环境读数为未知，不显示为 0。**有人 / 无人**表示占用状态，不表示人数。

## 照明

在**总览 › 照明**查看功能区的占用、开关、亮度、自动或手动状态、照度来源与更新时间。点击功能区查看回路及控制关系；手机拖动用于浏览楼层图，控制从功能区、单台或**整层控制**进入。

### 开关、调光与恢复自动

| 操作 | 对自动控制的影响 |
| --- | --- |
| 自动状态下**开灯 / 关灯** | 保持自动。人为关灯后须出现一次无人，才再次感应开灯。 |
| **调光**或执行调光场景 | 进入手动，查看**将在 HH:MM 恢复自动**。 |
| 手动状态下**开灯 / 关灯** | 仍为手动，并重新计时。 |
| **恢复自动** | 立即结束手动状态，交回自动控制。 |

手动调光按本区的**手动后恢复自动**时长或下一次定时执行恢复，先到者生效；工作与非工作时间的时长按项目设置区分。开关型控制器只能开灯或关灯，不能执行中间百分比调光。

执行后检查实际开关、亮度、控制状态与回路回报。照明功率按亮度和驱动功率估算，用电统计以验证后的计量数据为准。

<AccordionGroup>
  <Accordion title="自动效果不合适时" description="先查控制关系，再在批准范围内调整。">
    - **感应不符合预期**：检查占用来源、供电与跟随关系、设备在线状态，以及当前是否处于手动。
    - **恒照度不符合预期**：检查回路组的控制照度源。带 **★** 的是控制来源，其他诊断照度不直接参与控制。
    - **需要调整参数**：运营人员及以上在**照明控制参数**中核对楼层默认或功能区覆盖，并在已批准范围内调整。保存后检查网关及控制器同步结果。

    批准范围内的照明运营调整不改变设备期望配置版本，不需重新交付。缩短占用刷新属于网络变更，由配置人员或机构管理员处理，见[配置与交付](/platform/configuration-delivery#确认交付并转交运营)。
  </Accordion>
</AccordionGroup>

## 暖通空调

在**总览 › 暖通空调**先辨认风机盘管、多联机或只计量的分体空调，再查看室温、设定温度、模式、风速、运行状态与更新时间。

**显示室温与实际温控来源分开理解**：楼层图和功能区室温来自多功能传感器；风机盘管温控器使用内置传感器控制，多联机使用内机回风温度控制。

### 开关与调温

1. **核对对象**：查看本区设备及接入能力。分体空调仅计量；系统接入的可写点须已通过控制验证。
2. **核对可调范围**：按当前季节、机型限制、温度步长和空间授权操作。控制多台时，目标值应在各台都可设的范围内。
3. **确认并检查**：开关或修改设定后，看逐台回读与当前状态。设定已改变不代表室温已达到目标；温控开关也不等于压缩机实际运行。

**手动关闭空调**后，只有下一次时间表开机（含预启动）、**上班**或**恢复自动**解除关闭。有人进入、其他场景或需求响应不会因此重新开机。

非工作时间开启空调前，确认显示的结束时间；期满时若已进入开机时段则交回时间表，否则关闭。

<AccordionGroup>
  <Accordion title="不同系统的运行边界" description="舒适调整不能越过系统模式与原厂保护。">
    - **风机盘管**：待机、节能依已配置的占用策略运行；占用缺失按有人处理。冷热模式需符合实际水系统，四管制与两管制分别核对。
    - **多联机**：热泵系统改冷热模式可能影响同一冷媒系统及其他楼层。热回收系统的模式条件另行核对，不能套用风机盘管的待机与节能策略。
    - **分体空调计量**：用电中只能说明正在耗电，不能据此认定正在制冷或可由平台控制。
    - **需求响应**：仅在已接入且验证可执行时使用；只调整舒适状态设定，不开机，也不与待机、节能叠加。限温与设备保护始终有效。

    季节计划、原厂限温、面板锁与通信回退等由配置人员在应用设置和配置参数中核对，见[应用配置](/platform/configuration-delivery#应用配置)。
  </Accordion>
</AccordionGroup>

## 室内环境

在**总览 › 室内环境**查看已接入的温湿度、CO₂、PM2.5 等指标。先看单位、数据截至、采集位置与代表性，再判断当前情况；局部读数不直接代表整个楼层。

### 即时读数与统计结论

- **当前情况**：CO₂ 当前值按 1 分钟均值显示，用于即时查看和图层着色。
- **环境正常的空间**：按 CO₂ 1 小时均值、PM2.5 24 小时滚动均值，以及当前温湿度核对参考范围；只统计有空气质量传感器且网关在线的功能区。
- **空气质量档**：取 CO₂ 与 PM2.5 中较差的档位；不是正式环境检测的达标结论。若显示 VOC 指数，不能把它当作浓度。

参考范围和统计、告警条件取**配置参数**；**室内环境设置**用于核对采集位置与代表性，不另设一套阈值。具体指标以设备真实测量能力和验证结果为准。

持续偏高时，先核对数据质量与持续时间，再检查通风及实际使用情况。只有传感器不代表具备新风或净化控制；需要联动时须验证执行对象与控制主体。

长期趋势、参考范围内的时长和空间使用情况进入[分析与报告](/platform/analysis-reports#环境与空间使用)，持续异常进入[告警与维护](/platform/alarms-maintenance#处理告警)。

## 能源

在**总览 › 能源**查看今日与本月用电、分项、小时曲线、能耗强度和碳排放。先读计量口径、覆盖楼层与数据质量，再比较变化。

### 判断用电与费用

- **确认计量范围**：检查总表、分表和计入方式。分项可能已含在总表内，不能再加一次；看到计量点与设置不一致的提示时，先请配置人员核对。
- **区分数据性质**：查看**缺、估、补、复、换**标记，分别对应缺数、估算、补采、复位、换表，不能都当作连续实测数据。
- **比较同一口径**：当前时段与同等时段比较，结合工作时间、天气、空间使用及接入覆盖解释变化。完整历史比较进入数据分析。
- **看清费用与碳排放**：电费是按已登记电价和计费条件计算的估算；碳排放按适用因子版本与核算边界计算。没有适用因子的日期保留待设置或数据不完整，不套参考值。

能耗对标与节能基线须满足建筑类型、气候、有效历史数据等条件，不能仅凭当前读数得出节能结论。能源设置改变后，核对页面实际采用的计量口径与版本，不能只凭保存成功认定所有图表已重算。

图表的**数据表**用于核对同一口径的数值与质量说明；有入口时可**导出 Excel**。历史分析、费用与碳排放口径、报告见[分析与报告](/platform/analysis-reports#能耗与碳排放)。

## 场景与联动

从**场景**入口进入**场景、定时、联动、执行记录**。场景定义“做什么”，定时决定“何时做”，联动决定“什么条件下做”；定时和联动可引用同一个场景。

运营人员及以上按项目授权管理场景、定时与联动，登记工作时间与节假日表；查看人员只读，普通成员不使用这些入口。

<AccordionGroup>
  <Accordion title="场景：把一组动作组织起来" description="保存动作后，按需执行或供自动任务引用。">
    1. 打开**场景 › 场景 › 新建场景**，填写**名称、控制分组、动作**；调光时填写亮度，需要空调动作时另选暖通空调动作和设定值。
    2. 核对整个影响范围、可写能力与保护条件后**保存**，检查场景版本与各网关同步。保存成功不代表已同步或已执行。
    3. 在列表点击**执行**，核对对象与动作，再确认**执行场景**。到**执行记录**查看逐网络结果。

    当前照明场景使用本项目只含照明控制器的控制分组；空调动作作用于这些控制器所在功能区的风机盘管和多联机内机，不能直接选择任意空调对象。

    **上班**用于照明与空调恢复自动；**下班**用于照明关灯并保持自动、空调关闭。具体对象须实际接入且具备相应控制能力；项目温度限制依据为豁免时，豁免空间空调不受这些场景影响。下班场景不会提前关闭仍在非工作时间手动开机有效期内的空调，按原有效期处理。

    场景数量受型号与固件容量限制；被定时或联动引用的场景，先处理引用再删除。
  </Accordion>

  <Accordion title="定时：按项目的时间安排执行" description="引用场景，登记日期规则、时刻和例外日期。">
    1. 在**场景 › 定时**核对项目时区、**工作时间**与**节假日表**。工作日、调休和假期按项目已保存的节假日表判断。
    2. 点击**新建定时**，填写名称，在**执行**选择场景或**恢复自动·分组**；选择**日期、时间**，指定时刻时填写**时刻**。
    3. 按需填写**开始日期、结束日期、例外日期**；展开**跨午夜、夏令时与恢复**核对特殊规则，再保存。
    4. 检查启用状态、**同步、下次执行**，执行后查看记录。暂停任务用**停用**，跳过个别日期用例外日期。

    未登记当年节假日表时，工作日按周一至周五，**不会自动避开法定节假日**。“按通知填入”仍须保存。时间可引用工作时间开始或结束，随工作时间变化；不把默认值当作固定工作安排。

    停用定时不会结束照明手动状态；需要立即交回自动控制时，执行**恢复自动**。
  </Accordion>

  <Accordion title="联动：条件满足时触发动作" description="核对来源、持续时间、有效时段和恢复条件。">
    1. 打开**场景 › 联动 › 新建联动**，填写**名称、应用类型、有效时段**。
    2. 占用联动勾选有占用传感器的**触发来源**功能区，填写**条件、持续、恢复、执行**场景；任一所选功能区满足条件即触发，持续为 0 表示立即。新风、净化选择来源，核对页面显示的执行对象与配置参数。
    3. 核对控制主体与保护边界后保存，检查同步和执行记录；点击联动名称可**编辑、停用或启用**。

    回路内有人开灯、无人关灯与恒照度由照明控制器执行，无需重复创建同样的联动。新风的原厂 DCV 与平台 DCV（按需求调节通风）选择唯一控制主体；原厂控制时平台只监视，不再建立同样的控制联动。阈值与统计窗口引用配置参数。

    跨网络或跨系统动作逐段核对连接与可写能力。消防、排烟、应急照明与设备安全保护不在通用场景中设置；没有有效信号或执行对象时，不能把联动当作正在自动运行。
  </Accordion>
</AccordionGroup>

### 时间、断联与执行记录

**项目时区**决定显示与执行时间；时区未设置时明确按 UTC，不能用电脑或浏览器时区猜测。

<AccordionGroup>
  <Accordion title="高级时间规则" description="跨午夜、夏令时与关闭后恢复。">
    - **夜间安排**：00:00–05:59 的定时可选择按前一天日期规则。例如周六 00:30 按前一天时，按周五判断工作日。
    - **夏令时**：缺失的时刻可选切换后执行或当天跳过；重复的时刻只执行一次。
    - **关闭后恢复**：网关断电、离线或定时停用后恢复，可不补执行或只补当天错过的最近一次，不补全部历史任务。
  </Accordion>
</AccordionGroup>

- **云端断联**：实际下发并经现场断联验证的定时和同网络联动，按网关规则继续；跨网络、跨系统受影响部分不执行。网关断电或设备故障不能按同一条件判断。
- **执行记录**：按触发来源筛选，核对执行当时的名称、版本、目标和逐网络结果。后来修改或删除场景，不改写历史执行记录。

组控制显示**未回报 N 台**时先用**重新查询**。执行记录提供**重试 N 台**时，重新核对当前在线、仍在原场景目标内的对象；场景已改版或删除时，不能直接这样重试。

执行服务或网关同步未接入时，可以保存任务配置，但不能据此认定已同步或会执行。

## 大屏与展示

从**总览 › 大屏**打开当前范围的只读画面。项目或全部项目打开管理版式，楼宇或楼层打开值班版式；长期展示可用展示链接选择相应版式。

| 版式 | 适合展示 |
| --- | --- |
| **值班** | 一个或几个楼层的状态图、未恢复告警、设备在线率、用电与环境。 |
| **管理** | 项目或全部项目的用电、碳排放、能耗强度、在线率、告警及下一级比较。 |
| **公共** | 楼宇或楼层的环境与能源概况，可选横屏或竖屏；隐藏告警、设备与占用。 |

临时查看使用登录后的大屏；长期展示由机构管理员在**机构设置 › 展示链接**新建，核对名称、版式、范围，再**复制链接**到屏上打开。普通成员不使用大屏。

大屏只读，控制设备和确认告警回到对应运营页面。公开展示前核对可见范围；修改或撤销链接后检查已打开屏幕的实际结果。大屏同样要看更新时间与数据质量，不能把展示正常当作运行无异常。

展示链接管理见[机构与账户](/platform/organization-account)，历史评估与报告进入[分析与报告](/platform/analysis-reports)。
